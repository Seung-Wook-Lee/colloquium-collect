위원 자료 검색(RAG) 읽는법 — 2026-11-14 첫 판
=================================================

0. 한 줄 요약
   위원이 말하기 전에, 자기 서랍(자기 자료 + 공통 자료)에서 질문과 가장 가까운 문단 몇 개만 꺼내 보고,
   그 문단에 있는 것만 출처를 달아 말한다. 없으면 "자료 없음".

1. 다섯 단계와 이 코드
   1) 자료 준비   : 프로젝트 폴더(/mnt/project-files)의 위원공부·회의록·의장자료·페르소나·종목분석·뉴스브리핑·미스터역도산·미스차트
                    (기획안·팀Q·코랩·히스토리·99_지난자료·원본캡처는 읽지 않음. 같은 문서의 옛 Ver는 빼고 최신만)
   2) 텍스트 분할 : rag/chunker.py — 빈 줄·소제목에서 자르고 400~1400자로 맞춤. 문단 앞에 '문서 제목 > 소제목' 머리말.
                    csv는 줄마다 '열: 값'으로 바꿔 묶음(15KB 넘는 원자료 csv는 넣지 않음).
                    꼬리표: 위원(경로·파일 이름에서), 종목(유니버스 이름·티커·동의어.csv), 날짜(파일 이름), 종류, 출처·줄 번호.
   3) 벡터 임베딩 : rag/embedder.py — 제미나이 임베딩(gemini-embedding-001, 무료 등급, 768차원).
                    문서는 '문서용', 질문은 '질문용'으로 따로 바꿈. 바뀐 문단만 새로 바꿈(어제 것 재사용).
   4) 의미 검색   : rag/ask.py — 아래 2장.
   5) 답변 생성   : 위원(클로드)이 검색 결과 txt만 보고 말한다. 결과 끝의 [답할 때 규칙]을 따른다.

2. 4단계(검색)에서 하는 일
   ① 서랍 거르기 : --위원 미스세마이 → 미스세마이 꼬리표 문단 + 공통 문단만. 남의 폴더 자료는 안 나옴.
   ② 뜻 + 글자   : 뜻 검색(좌표 거리)과 글자 검색(BM25: 종목 코드·HBM4 같은 약어·숫자를 정확히)을 함께 돌려 순위를 섞음.
   ③ 질문 넓히기 : '마벨'이면 MRVL·마벨 테크놀로지도, 'HBM'이면 '고대역폭 메모리'도 글자 검색에 넣음(동의어.csv에 추가 가능).
   ④ 순서 다듬기 : 최근 자료일수록 가산점(최대 +25%, 60일마다 절반), 질문 종목 꼬리표 +20%, 한 파일에서 최대 2문단.
   ⑤ 자료 없음   : 뜻 유사도 0.70 이상이면 근거. 0.62~0.70은 글자 검색에도 잡혀야 근거
                   (질문에 영문 약어·숫자·종목이 있으면 그 낱말이 문단에 있어야 함). 아무것도 없으면 "자료 없음".

3. 쓰는 법(클로드 작업 창, colloquium-collect 폴더에서)
   색인 만들기(자료를 넣은 뒤·회의 전, 바뀐 것만 새로 해서 보통 1~2분):
       python rag/build.py
   질문하기:
       python rag/ask.py "HBM 공급 부족은 언제까지 가나" --위원 미스세마이
       python rag/ask.py "마벨 데이터센터 매출 비중" --위원 세마이 --종류 기업카드
       python rag/ask.py "의장이 정한 바닥 기준" --위원 미스차트 --이후 2026-11-01
       python rag/ask.py "엔비디아 황 해임" --전체 --저장
       python rag/ask.py --질문파일 오늘질문.txt --저장      (한 줄에 '위원<TAB>질문')
   결과 저장 위치: /mnt/project-files/위원검색/결과/YYYYMMDD/검색_HHMMSS_위원.txt
   색인 위치     : /mnt/project-files/위원검색/색인/ (문단.csv · 벡터.npy · 색인정보.txt)

4. 비용·한도
   제미나이 임베딩 무료 등급: 분당 100문단·약 3만 토큰. 코드가 분당 90문단·2만5천 토큰 안쪽으로 천천히 보냄.
   처음 한 번 전부(약 1,250문단)는 30~40분, 그 뒤로는 새 문단만이라 1~2분.
   하루 한도에 걸리면 받아 둔 것을 저장하고 멈춤 → 다음에 돌리면 이어서 함.

5. 고칠 수 있는 곳
   rag/config.py   : 읽는 폴더, 문단 크기, 위원 이름 표기, 문턱(0.70·0.62), 최신 가산점, 결과 개수
   rag/동의어.csv   : 줄임말·같은 말(종목이면 종목번호, 아니면 비움)

6. 아직 안 한 것(다음 단계 후보)
   - 다시 고르기(재순위): 상위 20문단을 한 번 더 정밀하게 고르는 모델. 지금은 무료로 붙일 수단이 없어 보류.
   - 질문 쪼개기: "마벨과 브로드컴 비교"를 두 질문으로 나눠 찾기.
   - GitHub Actions 판: 지금 자료 대부분(기업카드·최근 회의록·톰스뉴스 정리)이 드라이브가 아니라 프로젝트 폴더에만 있어서,
     Actions는 이 자료를 못 봄. 드라이브로 자료가 모이면 같은 코드를 Actions에 붙일 수 있음.

7. 기획기사 넣는 자리(11/14 의장 "기획기사도 RAG로 위원 공부")
   폴더: /mnt/project-files/위원공부/기획기사/  (하위 폴더 마음대로, 예: 2026-11/)
   파일 이름: <위원이름>_기사_<언론사>_<제목>_<YYYYMMDD>.txt   예) 미스세마이_기사_매경_HBM4 공급망 점검_20261114.txt
              여러 위원이 볼 기사는 공통_기사_… (공통 문단 = 모든 위원 서랍에 들어감)
   파일 첫머리 몇 줄: 언론사 / 날짜 / 원제목 / 주소(URL) 을 적고, 그 아래 본문 또는 요약.
   꼬리표는 자동: 위원(파일 이름 첫머리), 종목(본문 속 이름·티커), 날짜(파일 이름), 종류 '기획기사'.
   찾을 때: python rag/ask.py "HBM4 공급망" --위원 미스세마이 --종류 기획기사
   전문 저작권: 원문 전체 대신 요약 + 핵심 숫자 + 주소를 권장(공부용, 밖으로 내보내지 않음).
   수집 경로(네이버 등)는 '외신 중심 뉴스 수집 방법 찾기' 스레드에서 정함 → 그 결과 txt를 이 폴더에 떨어뜨리면 다음 색인 때 자동으로 들어옴.
